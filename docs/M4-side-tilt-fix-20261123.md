# M4 SIDE_LOCK 测斜“没反应”的根因与验证计划（2026-11-23）

> 背景：12:13 的 faces=2 实车日志里 `PROBE_SIDE_LOCK,h=167,...,h1=167.0,h2=167.0,h3=176.0,corr=0.0,warn=0`，
> 测斜修正从未动作。本文给出代码级根因、已落地的修改、以及插回 ST-Link 后的台架/实车验证计划。

## 0. 结论（TL;DR）

- `corr` 一直是 0 **不是**“车真的平行”，而是 **h2 从来没有被重新采样**：
  `probe_side_lock_sample()` 只在 `side_ring_n >= 5` 时返回 true，而 h1 之后样本环没有清零，
  所以 stage 3 第一拍就“采样成功”，`h2 = median(同一批 h1 样本) ≡ h1`，
  `corr = atan2(h2−h1, 60) = 0`。**成功路径上 corr 不可能非 0。**
- 引入时间：commit `7bded7f`（11:57）把“原地 +5° 两点法”改成“沿面 60 mm 平移两点法”时，
  h2 前的 `side_ring_n = 0U` 丢了（旧代码在 stage 2 里有这一句）。此后 11:31~12:13 的
  **10 次成功 SIDE_LOCK 全部 h1==h2**，与“车是否平行”无关。
- 所以“故意斜放 10~15°”的检验在旧固件上**也只会得到 h1==h2 / corr=0**，会给出错误结论；
  必须先烧本次修复的固件再测。
- 修复后：host 34/34 通过（新增回归用例 `probesidetilt`），固件 `FLASH 112736 B (21.67%)` /
  `RAM 11872 B (12.08%)`，bin 112736 B。

## 1. 根因链（代码级）

```
SIDE_LOCK stage 1：probe_side_lock_sample() 采 5 帧 → side_ring_n = 5 → side_h1 = median(...)
SIDE_LOCK stage 2：沿面平移 60 mm（编码器走 60.3 mm 才刹车）
SIDE_LOCK stage 3：probe_side_lock_sample()  ← side_ring_n 仍是 5 → 立即返回 true
                   side_h2 = probe_side_median(c, 5)  ← 还是 h1 那 5 个数
                   atan2(0, 60) = 0 → 低于 1.5° 死区 → corr = 0
SIDE_LOCK stage 4：退回原点 → probe_turn_to(corr=0)
SIDE_LOCK stage 5：side_ring_n = 0 → 重新采 5 帧 → side_h3（这一处清环了，所以 h3 会变）
```

关键函数：

- `Control/line_follower.c` `probe_side_lock_sample()`（约 1508 行）：
  只追加、只在 `n>=5` 时返回 true，**自己不负责清环**（注释里写着“h2/h3 前把 side_ring_n 清 0”，
  但 h2 这一路没有执行）。
- stage 3（约 1995 行）修复前直接调用采样函数，没有清环。
- 旧实现（`4aab01e`，被 `7bded7f` 替换）在 stage 2 旋转前有 `c->side_ring_n = 0; c->side_ping_since = now;`，
  改成平移法时这段被删掉，只在 stage 4（h3 前）保留了一份。

## 2. 为什么原来的判据表失效

| 原判据 | 问题 |
|---|---|
| `h1≈h2` → 车平行 | **恒真**（h2 复用 h1 的样本），不含任何信息 |
| `ds≈60` → 平移真的走了 | 只说明编码器计数到 60 mm；轮子打滑/顶住空转时也会是 60 |
| `corr=0` → 不需要修正 | 恒真（atan2(0,60)=0） |

因此“先看新加的 ds 再决定”仍然不够：**ds 只能排除“编码器完全没动”**，排除不了“轮子空转”。
要区分“真平行”和“车没动”，只有两条路：

1. 人为把车摆成已知 10°（本计划的台架用例）；
2. 用卷尺/地面标尺独立量出车真的走了 60 mm。

## 4. 台架验证计划（插回 ST-Link、烧 `build/Debug/line-following.elf` 后）

### 4.0 先确认烧进去的是这一版

上电日志多了一个标记：

```
PROBE_BUILD,swaplr=0,h_pred=1,tilt=2
```

`tilt=2` = 「60 mm 平移 + h2 重采」。旧版只有 `swaplr=0,h_pred=1`。
bin 时间戳应为 2026-11-23 12:32 之后、大小 112736 B。

### 4.1 摆位

- 150 mm 宽面朝向车头，云台轴距面约 **180 mm**；箱体在左（默认 `probe_side_left=1`、`side_us=2400`）。
- 地面贴一条与面平行的基准线；车体轴线相对基准线摆成 0° / ±10°（用量角器或 3-4-5 直角尺）。
- 用 `side`（自走），**不要用 `side push`**（手推模式跳过测斜）。
- 每组重复 3 次，每次重新摆位（不要靠上一次的残留姿态）。

### 4.2 用例与期望值（60 mm 基线，左侧面）

| 组 | 摆位 | 期望 ds | 期望 h2−h1 | 期望 corr | 判定 |
|---|---|---|---|---|---|
| A1~A3 | 平行（0°） | 60±5 | ≤ ±3 mm | 0（<1.5°） | 3 次 h2−h1 的极差 ≤ 4 mm |
| B1~B3 | 车头向箱面偏 10° | 60±5 | ≈ −10.6 mm | ≈ −10.4°（右转） | |corr−(−10.4)| ≤ 3° |
| C1~C3 | 车头离开箱面 10° | 60±5 | ≈ +10.6 mm | ≈ +10.4°（左转） | |corr−(+10.4)| ≤ 3° |
| D | 顶住不动（轮子空转） | 60（编码器） | 0 | 0 | **只看现象**：ds≈60 但车没动，说明 ds 不能单独当“真走了”的证据 |

> 符号：车头“向箱面偏”= 车头比车尾更靠近箱子；左侧面时前进会让 h 变小。
> 如果 B/C 两组都出现信号但**符号相反**，先查 `probe_side_left` 与 `probe_side_us` 是否配错。

### 4.3 记录格式

每次记录两行（固件日志 + 卷尺）：

```
PROBE_SIDE_LOCK,h=...,h1=...,h2=...,h3=...,corr=...,warn=...,ds=...
实际摆位 θ=...°   卷尺: 车实际前进 ____ mm（可选，D 组必测）
```

### 4.4 结果解释

| 现象 | 结论 | 下一步 |
|---|---|---|
| `ds≈0`、`warn=6` | 编码器完全没走 | 查电机使能/供电/轮子是否被挡 |
| `ds≈60`、斜 10° 时 `h2−h1≈0` | 轮子转了但车没动（打滑），或声呐没看到这个面 | 卷尺量实际位移；听轮子是否空转；必要时改连续采样（§6） |
| `ds≈60`、斜 10° 时 `h2−h1≈10.6`、corr≈±10° | 测斜正常，之前“没反应”确实是车真的平行 | 转 §5 跑 faces=2 |
| corr 抖动 >4° | 60 mm 基线信噪比不够 | 见 §6 备选方案 |

## 5. 自动 faces=2 复核（测斜修好后）

1. 同一摆位跑 `faces=2`，看面 1 的 `PROBE_SIDE_LOCK`：
   - `h2` 必须与 `h1` **独立**（不再出现“每次都恰好相等”）；
   - `warn=0`、`ds≈60`；
   - `corr` 通常应 <5°（TURN_PAR 刚把车转平行）。若稳定在 ±8~15°，说明 TURN_PAR 的 φ 有系统偏差，
     应去查 AIM/转向标度，而不是继续调测斜。
2. 注意：12:13 的面 2 失败（`SIDE_LOCK,h1=380`）是 **LEG 落点/窄面丢失**的独立问题，
   本次测斜修复不会自动解决，仍按《M4-gate0-20261123.md》§6 的精度收尾处理。

## 6. 如果实测信噪比不够（备选方案，按优先级）

1. **加长基线**：`LF_SIDE_TILT_SHIFT_MM` 60→100/120 mm（10° 信号 17.6/21 mm），
   代价是宽面边缘余量变小；只对第一面宽面做，可接受。
2. **连续采样拟合**：把 60 mm 平移段按 60 ms 连续采 h(s)（约 13 帧），最小二乘斜率 `tanψ`，
   同时用“有效帧数/实际位移”做卡住判据。和 `SIDE_MOVE` 里现成的 `side_move_mono/dh/ds` 是同一套思路，可复用。
3. **复用 SIDE_MOVE 的测斜**：`LF_SIDE_MOVE_DRIVE` 已经在 100 mm 行程上做单调漂移检测，
   但修正发生在扫描之后；作为兜底可以，不能替代 SIDE_LOCK 的“先转正再扫”。
