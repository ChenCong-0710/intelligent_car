## 二、现板可执行硬件改造方案（先由软件数字孪生 `hwemu` 验证，再动手改焊）

> **工作原则**：严禁盲拆盲焊。先用软件模式测通整圈 → 开启 `1:1` 硬件模拟 PID 仿真模式（`set hw_emu 1` / `host_station.py hwemu`）在实车上跑出最稳参数 → 串口运行 `hwmap` 生成专属 BOM 替换值 → **按下面对照表先做不损伤焊盘的跳线/换阻容改造，确有必要再动飞线**。

### 2.1 零焊接动作：必查跳线配置

| 位号 | 现板定义 | 建议固定配置 | 物理原因与效果 |
| :--- | :--- | :--- | :--- |
| **`JP_V`** | `1-2`: `BASE_BOTTOM <-> PWM_MID` (2.5V)<br>`2-3`: `BASE_BOTTOM <-> R68 (6.2kΩ->GND)` | **插在 `2-3`** | 插在 `1-2` 时 `V_BASE` 最低被锁死在 `2.50 V`（基速占空比 `D0 ≥ 48.5%`，空载/低阻赛道极易过快冲出弯道）；插在 `2-3` 可将 `V_BASE` 连续下调至 `1.384 V`（`D0` 覆盖 `0% ~ 100%`） |
| **`JP_I`** | `1-2` 闭合：将 `U6D` 积分输出 `V_I` 经 `R47(100kΩ)` 并入 `PID_SUM_N` | **常规调 PID 时先拔掉** | 原板 `C61` 为 `CL10B105KA8NNNC` (0603 X7R，直流偏压降容严重且与 `R57=1MΩ` 构成 `0.159 Hz` 泄漏极点)，连续弯道易积分饱和甩尾；只有高速长直道存在稳态偏置且确认有必要时再插上并配合高精度薄膜/C0G 电容 |

### 2.2 零飞线：纯换焊贴片阻容即可完成的 4 项核心升级

> 以下位号与阻容值均直接提取自 [live-main-netlist.json](file:///c:/Users/Seraphina/Documents/ESD/firmware/line-following-car/docs/live-main-netlist.json)，换焊时请用万用表电阻档再次确认焊盘所属网络。

1. **★ 最优先改造（扩展 D 级微分阻尼 3×~10×）：换焊 `C50` 与 `R54`（可选调 `R61`）**
   - **现状瓶颈**：`C50 = 100 nF`、`R54 = 22 kΩ`、`R55 = 4.7 kΩ`、`RV_D = 100 kΩ`、`C60 = 10 nF`、`R61 = 20 kΩ`。当前整条 D 支路最大微分时间常数仅为 $(R_{55}+R_{V\_D})C_{50} = 104.7\text{ k}\Omega \times 100\text{ nF} = 10.47\text{ ms}$。在 $K_p = 2 \sim 5$ 时，等效微分相对超前时间常数只有 $2 \sim 5\text{ ms}$，且 $72.34\text{ Hz}$ 高通拐点使低频弯道入弯角速度阶段几乎给不出有效阻尼，这是纯硬件连续 S 弯过冲甩尾的头号原因。
   - **改焊方法**（依据 `hwemu` 测得最优 `hw_kd_ms` 选一档，**换 `C50` 必须等比减小 `R54`** 以维持输入高频噪声截止时间常数 $\tau_1 = R_{54}C_{50} \approx 2.2\text{ ms}$）：
     - **温和档（`hw_kd_ms` 上限扩至 `~49 ms`）**：将 `C50` 换为 **`470 nF`**（优先耐压稳定的 C0G/薄膜或大尺寸 X7R），同时将 `R54` 由 `22 kΩ` 换为 **`4.7 kΩ`**。此时 `RV_D`（0 ~ 100 kΩ）可将微分时间常数平滑调至 `2.2 ms ~ 49.2 ms`。
     - **强阻尼竞速档（`hw_kd_ms` 上限扩至 `~105 ms`）**：将 `C50` 换为 **`1 µF`**，同时将 `R54` 由 `22 kΩ` 换为 **`2.2 kΩ`**。
   - **求和权重微调（仅在 `RV_D` 不够或需独立缩放 D 贡献时）**：若需要直接加倍 D 支路增益，可将求和输入电阻 `R61`（`V_D -> PID_SUM_N`，原 `20 kΩ 0.1%`）改为 `10 kΩ`；反之需要削弱 D 噪声时改为 `33 kΩ ~ 47 kΩ`。

2. **P 级比例最小增益下限过高时：换焊求和电阻 `R60`**
   - **现状瓶颈**：`U6B` 比例级为 $K_{p\_stage} = (R_{49}+R_{V\_P})/R_{48} = 1 + R_{V\_P}/10\text{k}\Omega \in [1.0, 11.0]$，`R60 = 20 kΩ`，反馈 `R62 = 20 kΩ`，导致即使把 `RV_P` 逆时针拧到最小，总比例增益最低也只能降到 `1.0`（结合低基速与两路同时压黑时的 `e ≈ ±0.5Δ`，极易让 PWM 直接打满 0%/100% 饱和）。
   - **改焊方法**：先确认不是探头外侧接反且在 `hwemu` 中证实需要 `hw_kp * (20/hw_r60) < 1.0`，再将 **`R60`**（`V_P -> PID_SUM_N`，`0.1%`）由 `20 kΩ` 改为 **`47 kΩ`**（总比例增益范围平移至 **`0.426 ~ 4.68`**，可覆盖柔和压线过弯与中高增益）。

3. **消除外侧边缘误差回落与死区不均：调整四路红外加权电阻 `R39 / R40`（`L2/R2`）**
   - **现状瓶颈**：`R39=R40=150 kΩ (L2/R2)`，`R41=R42=300 kΩ (L1/R1)`，`R43||R45 = R44||R46 = 50 kΩ`，名义权重为外侧 `1/3`、内侧 `1/6` (`2:1`)。在 `20 mm` 黑带下，黑带向右滑出时：`W-B-B-W` (`0`) → `W-W-B-B` (`+0.50Δ`) → `W-W-B-W/B` (`+0.33Δ`) → `W-W-W-W` (`0`)，出现**刚只剩外探头看到黑线时误差反而下跌 33%** 的非单调凹坑！
   - **改焊方法**：当 `hwemu` 使用 `hw_w_out = 0.50 ~ 0.67` 明显改善边缘拉回能力时，将外侧电阻 **`R39`、`R40`**（`0.1%`）由 `150 kΩ` 同改为 **`100 kΩ`**（外侧权重升至 `0.50`，单外路见黑与右两路见黑同为 `0.50Δ`，完全抹平凹坑）或 **`75 kΩ`**（外侧权重 `0.67`，单外路误差比两路见黑更大，呈严格递增）。
   - ⚠️ **对称提醒**：更换 `R39/R40` 必须同时测量 4 路白底静态基准 $V_{w,i}$，避免因外侧权重放大同时放大左右探头固有零偏失调。

4. **外设抗浮空小改造（可选补焊）：`SERVO_PWM` 与 `GPIO` 安全下拉**
   - **`R120` 后级补 `47 kΩ` 下拉**：对照 `F05` 审查，`SERVO_PWM`（`R120 = 100 Ω` 与 `J_SRV.1` 之间）未配置硬件下拉电阻，极少数舵机在上电/切电源瞬态对高阻线易微抖，可用漆包线或跨焊一颗 `0603 47 kΩ` 至就近 `GND`。

### 2.3 少数关键飞线改造（解决纯硬件“内轮滑行 + 全白丢线归零”两大物理天花板）

若通过 `hwemu` 的对比测试（`hw_coast 1` vs `hw_coast 0`）发现仅调 PID 仍过不了高速连续弯，根因通常来自下面两处**非参数瓶颈**：

1. **改造 `U4` 实现纯硬件【驱动/制动 Slow Decay】代替【滑行 Fast Decay】（收益最大）**
   - **原电路机理**：当单片机拔掉或 `MODE_MCU = 0` 时，`U4 (SN74AHCT157)` 把 `ANA_PWM_L` 送到 `DRV_AIN1`、`ANA_PWM_R` 送到 `DRV_BIN1`，而 **`DRV_AIN2 (U4.7)` 与 `DRV_BIN2 (U4.12)` 在 `B` 通道全被硬接 `GND`**！根据 `DRV8833` 真值表，此时固定为 `10/00`（Driven / **Coast 滑行**），当外弯需要急刹内轮降速到 `0%` 时，内轮并没有刹车而是靠惯性继续往前滑行；且低占空比区非线性死区比软件 `Slow Decay` 大得多。
   - **少量飞线可行方案**（二选一）：
     - **方案 A（推荐，加一颗小板 `74AHCT14` / `74LVC2G04` 反相器做真 Slow Decay）**：翘起并隔离 `U4.2`、`U4.5`、`U4.11`、`U4.14` 四个硬件源输入脚（**切记不要断开 `U4.8` 芯片地脚，也绝不能在未断开 `U10.1/U10.14` 前直接把 `U4.2/11` 接 `SYS_5V`**！）。随后将 `U4.2`、`U4.11` 接 `SYS_5V`，并将原 `ANA_PWM_L / ANA_PWM_R`（来自 `U10.1 / U10.14`）经反相器取反后分别喂给 `U4.5 (2A -> DRV_AIN2)` 与 `U4.14 (4A -> DRV_BIN2)`。此时在使能运行期间（`G#=0`），PWM 高有效期间为 `IN1=1, IN2=0`（正向驱动），关断期间自动进入 `IN1=1, IN2=1`（主动制动 Slow Decay）；而在上电 2 秒静止或障碍物锁停时，`U4.15 (MOTOR_nENABLE)=1` 仍会把 `U4` 四路输出强拉 `0000`，安全性 100% 保持！
     - **方案 B（更简单验证）**：如果仅仅想避免左右轮低速死区不一致而不改拓扑，可在确认左右轮静止电压不对称后，仅微调 `U7B/U7C` 混合级偏置或更换同一批次左右摩擦一致的 `N20` 电机。

2. **加装【2 路比较器丢线保持飞线小板】（解决纯硬件全白回正冲出赛道）**
   - 当高速冲过 `20 mm` 黑带致 4 路全白时，差分加权 `PID_E` 自动归回 `2.50 V`，小车会立刻取消差速直线冲出。可在后续拓展小板上用一颗双路比较器检测 `IR_TRACK_0` 与 `IR_TRACK_3` 是否过白阈值，全白瞬间锁存最后一次有效越界方向并微降 `V_BASE`，这部分在软件循迹上目前已完美实现，纯硬件如确要冲击高难度赛道可做小模块飞线接入 `PID_E` 或 `V_BASE`。

## 三、下一版原理图与 PCB 设计优化方向（Rev 2.0 架构演进清单）

结合本轮软硬联调、实体排针核对和视频实测暴露的问题，下一版主扩展板与红外子板应重点按以下 **8 个方向** 重构：

| 类别 | 现板痛点 / 风险 | 下一版（Rev 2.0）明确改进方案 |
| :--- | :--- | :--- |
| **1. 模拟 PID 参数区与器件选型** | `C50=100nF` 偏小致微分极弱；`RV_P` 下限锁死 `Kp≥1.0`；`C61` 用 0603 X7R 直流偏压损耗大；`R39/R40=150k` 边缘跌落 | ① 默认 `C50` 扩至 **`470 nF (C0G/薄膜)`**、`R54 = 4.7 kΩ`，`R60` 预留 **`33 kΩ ~ 47 kΩ`** 可选位；<br>② `C61` 换为 **`1 µF` 薄膜电容** 或高耐压大封装 1206 C0G；<br>③ `R39/R40` 调为 **`100 kΩ`**（外侧 `0.50` 权重）或设双排针跳线方便在 `2:1` 与 `3:1` 权重间零焊接切换；<br>④ 取消 `JP_V` 锁死高基准的 `1-2` 接法或明确标注 `JP_V` 为量程切换 |
| **2. 纯硬件内轮制动与丢线保持** | `U4` 硬件模式 `IN2=0`（只能滑行，无法慢衰减制动）；无“全白失线保持最后转向”硬件电路 | ① 硬件电路直接支持 **Slow Decay（主动制动 PWM）**（默认 `U4` 输入对支持反相切换）；<br>② 增加 **四路黑线存在窗口检测 + 末方向锁存器 (`74HC74`)**，在全白失线瞬间保持最后弯道差速并自动降基速搜索 |
| **3. 逻辑门裕量与舵机下拉完善** | `D3/D4 (BAS316) + R89 (100kΩ)` 二极管 OR 门在极端高低温下存在裕量隐忧（F06）；`SERVO_PWM` 缺 `R120` 后级对地 `47kΩ` 下拉（F05） | ① 用真正单门 OR 芯片 **`SN74AHCT1G32`** 取代二极管 OR 门 `D3/D4 + R89`；<br>② 在 `R120 (100 Ω)` 与 `J_SRV.1` 之间补焊 **`47 kΩ` 对地电阻**（与 `PA15` 前级 `R113=47kΩ` 对称） |
| **4. 三路按键硬件强壮性** | `PD0 (SW2)` 经过 `10k/47k/100k` 电阻网络接在 `U3` 之前，丝印/极性极易被固件误判；核心板 `PD15 (SW2)` **无外部上拉电阻**，仅靠 STM32 内部弱上拉 | ① 将 `KEY_TRACK_MCU (PD0)` 统一改为接至 `3.3 V` 上拉链路（与 `PD1` 完全对称的 `10kΩ->MCU_3V3 + 100nF + 低有效`），并用 3.3V/5V 隔离二极管或双开关触点与 `U3` 硬件启动解耦；<br>② 在主扩展板 **`J_C1.5 (PD15)` 处额外预留/加焊一颗 `10 kΩ -> MCU_3V3` 外部上拉 + ESD TVS**，提升 `CORE_KEY` 抗干扰能力 |
| **5. 核心板存在检测与自检** | `J_C2.6 (MCU_PRESENT_n)` 一旦虚焊，`U3.2 MODE_MCU=0V` 会无声屏蔽大部分 MCU 输出，调试极其隐蔽 | ① 在 `MODE_MCU` 节点增加一只贴片指示 LED（如绿色“MCU 控制接管灯”）+ 测试点 `TP_MODE_MCU`；插上核心板正常识别后该 LED 立刻亮起，虚焊一目了然；<br>② 保留通孔 `HC-PM254` 长焊盘，丝印标清 `Pin 1` 缺口与核心板方向防呆 |
| **6. 外设供电与接口冗余** | `Q5 (BSS138BK)` 激光由 `PC8 (3.3V)` 直接驱动，3.3V $V_{GS}$ 下导通能力需核对电流余量；`J_BT` 丝印易插反 | ① 激光器低侧驱动改用明确 $V_{GS(th)} < 1.2\text{ V}$、`2.5 V / 3.3 V` 额定 $R_{DS(on)}$ 的逻辑电平 NMOS（如 `AO3400A` / `SI2302`），或并入 `5V` 电平缓冲；<br>② `J_BT` 使用带防呆卡扣的立式/卧式插座，并在顶层丝印明确标出 `1:ST 2:RX 3:TX 4:GND 5:5V 6:EN` 与**“对接 HC-04 丝印交叉口诀”** |

## 四、三路按键与 MCU 输出故障审查及快速定位手册

针对您关心的**“单片机是否能正常检测到三个按键信号、为什么硬件模式下按键没问题但 MCU 可能检测不到，以及 MCU 输出如何快速查错”**，我们逐根引脚核对网表与核心板电路后，整理出明确结论与 3 分钟排查流程。

### 4.1 关键结论：三个按键在硬件上都能被 MCU 正常检测，但我们刚刚修复了一个固件里的 P0 级极性错误！

经核对主板网表 [live-main-netlist.json](file:///c:/Users/Seraphina/Documents/ESD/firmware/line-following-car/docs/live-main-netlist.json) 与核心板原理图 [STM32G474VET6V1.1原理图.pdf](file:///C:/Users/Seraphina/Documents/ESD/DataSheet/STM32G474VET6V1.1%E5%8E%9F%E7%90%86%E5%9B%BE.pdf)：

1. **循迹键 `SW2 -> PD0`（★ 刚刚捕获并修复的 P0 Bug）**
   - **真实硬件电路**：`SW2` 按下将 `KEY_TRACK_N` 短接到 `GND`（松开时由 `R118 = 10 kΩ` 上拉至 `SYS_5V`）。主板确实有一级反相器 `U3 (74AHCT14)` 把 `KEY_TRACK_N` 反相为 `KEY_TRACK_P`，**但 `U3` 反相器仅喂给了纯硬件触发器 `U16.3`！**
   - **`J_C1.19 -> PD0` 采样的是 `U3` 之前的信号 `KEY_TRACK_N`**：经 `R124 (47 kΩ)` 和 `R114 (100 kΩ)` 分压进入 `PD0`。
     - **未按下时**：$V(\text{KEY\_TRACK\_N}) \approx 4.682\text{ V}$，$V(\text{PD0}) = 5.0 \times \frac{100}{10 + 47 + 100} = 3.185\text{ V}$ -> **高电平 (`SET`)**。
     - **按下时**：$V(\text{KEY\_TRACK\_N}) = 0\text{ V}$，$V(\text{PD0}) = 0\text{ V}$ -> **低电平 (`RESET`)**。
   - **修复结果**：旧版固件误以为 `PD0` 接在 `U3` 后面而写了 `== GPIO_PIN_SET`（高电平有效），上电会误判“一直被按住”而屏蔽真实按键！现已在 [Board/board.c](file:///c:/Users/Seraphina/Documents/ESD/firmware/line-following-car/Board/board.c) 中的 `board_track_pressed()` **修正为 `== GPIO_PIN_RESET`（低电平有效）**，且保持 `PD0` 为 `GPIO_NOPULL`（绝不开内部上拉以免与 `5V` 分压电阻互灌）。

2. **探测键 `SW3 -> PD1`（电路与代码一致，正常）**
   - `SW3` 直接连接 `KEY_PROBE_MCU <-> GND`，主板配 `R119 = 10 kΩ` 上拉至 `MCU_3V3` 与 `C88 = 100 nF` 滤波电容。未按下 `3.3 V` (`HIGH`)，按下 `0 V` (`LOW`)，`board_probe_pressed()` 为 `== GPIO_PIN_RESET`，正常。

3. **核心板用户键 `SW2 -> PD15`（电路与代码一致，但依赖内部弱上拉）**
   - 根据核心板原理图，`SW2` 一端接 `PD15`，另一端接 `GND`，**核心板上没有任何外部上拉电阻**，完全依赖 [Board/board.c](file:///c:/Users/Seraphina/Documents/ESD/firmware/line-following-car/Board/board.c) 配置的 `GPIO_PULLUP`（约 `40 kΩ` 内部弱上拉）。未按下 `3.3 V` (`HIGH`)，按下 `0 V` (`LOW`)，`board_core_pressed()` 为 `== GPIO_PIN_RESET`，正常。

### 4.2 为什么“纯硬件模式按键好用”，换成 MCU 却可能“没反应”？快速定位 4 步法

一旦实车出现按 `SW2/SW3/CORE_KEY` 无反应，**不要猜代码**，按下面 4 步可在 2 分钟内精准定位到“软件 / 排针接触 / 焊接阻容 / 芯片本身”的哪一环：

#### 第 1 步：用新增蓝牙命令 `io` 直接看 STM32 引脚原始高低电平
串口/上位机输入命令 **`io`**，固件会直接读取 STM32 GPIO 寄存器并输出：
```text
IO_IN,PD0=H(track=0),PD1=H(probe=0),PD15=H(core=0),PC4_nFAULT=H,PC10_BT=H,PC6_ECHO=L
IO_ENC,TIM4_L=0,TIM3_R=0,ADC=3120,3105,3090,3140
```
分别**按住**三颗按键时再连发 `io`：
- **预期变化**：按哪颗键，对应的 `PD0` / `PD1` / `PD15` 必须从 **`H (0)` 跳变为 `L (1)`**，松开变回 **`H (0)`**。
- **若 `io` 显示从 `H` 变 `L`（说明电气和 GPIO 完全正常），但短按依然不触发功能**：
  1. **按压时间过短或过长**：固件 [Core/Src/main.c](file:///c:/Users/Seraphina/Documents/ESD/firmware/line-following-car/Core/Src/main.c) 需要按住 **`>= 25 ms`** 才算有效消抖（松开触发短按，`>= 1000 ms` 触发长按校准）。
  2. **处于状态保护拒绝期（最常见！）**：例如还没运行过 8 秒红外校准 (`cal` / 长按 `PD1` 或 `PD15` 1 秒)，直接按 `SW2` 循迹键启动会因 `!cal.valid` 触发 `FAULT_UNCALIBRATED` 或串口拒签（可同时观察蓝牙提示 `DENIED` 和核心板红/蓝灯状态）；或者处于 `MOTOR_CAL` / `CALIBRATING` 状态期间按键会被拒绝或转成紧急停机。

#### 第 2 步：若按住按键时 `io` 始终显示 `H`（电压下不去 `0V`）→ 万用表顺藤摸瓜
红表笔测点、黑表笔接 `GND`，对照实网定位：
- **查 `SW2 (PD0)`**：
  1. 测 `SW2.1 (KEY_TRACK_N)`：松开应为 `~4.68 V`，按下应跌到 **`0.0 V`**。
     - 若按下不跌到 `0 V`：按键本身虚焊/坏了，或 `SW2.2` 未接通 `GND`（注意：纯硬件模式若好使，说明 `SW2 -> KEY_TRACK_N -> U3.9` 本身没问题，问题必在 `R124 -> J_C1.19` 支路！）。
  2. 测 **`R124` 两端与核心板排针 `J_C1-19 (PD0)`**：松开应为 **`3.185 V` 左右**，按下应跌到 **`0.0 V`**。
     - 若 `KEY_TRACK_N` 正常跌 `0 V`，而 **`J_C1-19` 始终高于 `2 V` 或悬空**：检查 `R124 (47 kΩ)` 是否虚焊/错贴为过大阻值，`R114 (100 kΩ)` 是否开路，或 **`J_C1-19` 排母/排针冷焊未导通**。
- **查 `SW3 (PD1)`**：
  - 测 **`J_C1-20 (PD1)`**：松开应为 **`3.3 V`**，按下应跌到 **`0.0 V`**。按下不跌 `0 V` 查 `SW3` 焊盘或 `J_C1-20`；松开也是 `0 V` 查 **`C88 (100 nF)` 是否短路** 或 `R119 (10 kΩ)` 未贴/虚焊。
- **查核心板 `SW2 (PD15)`**：
  - 测核心板 `SW2.1` 或 **`J1-5 (PD15)`**：程序正常运行后应为 **`3.3 V`**（若核心板未烧写运行固件或尚未执行 `gpio_init()` 开启内部上拉，此脚默认高阻不是 `3.3 V`，注意区分！），按下跌 **`0.0 V`**。若松开被主板意外拉低，查扩展板 `J_C1-5` 焊盘有无连锡到旁边的地或相邻引脚。

### 4.3 MCU 输出通路审查与 `outtest` / `bench` 快速排错指南

即使 STM32 的 GPIO 成功翻转为高电平，**扩展板上仍有门控逻辑决定信号能否真正送达外设！** 所有 MCU 输出通道按门控路径分为 **两大组**：

#### A 组：受 `J_C2.6 (MCU_PRESENT_n) -> U3.2 (MODE_MCU)` 门控的 5 组执行通道（最隐蔽故障点！）
- **门控链路**：核心板 `J2-1/2/3/4/6` 内部短接 `GND` → 插入主板 `J_C2-6 (MCU_PRESENT_n)` → 经 `R11 (1 kΩ)` 进入反相器 `U3.1` → `U3.2` 输出 **`MODE_MCU = 5 V`** → 分别选通 **`U4 (DRV8833 驱动合路)`** 与 **`U18 (外设合路)`** 的 MCU `B` 通道。
- **致命隐蔽故障**：**一旦 `J_C2.6` 排针/排母虚焊，或核心板没插到底**，扩展板 `R13 (10 kΩ -> SYS_5V)` 会把 `MCU_PRESENT_n` 拉高到 `5 V`，导致 **`MODE_MCU = 0 V`**！此时核心板能通过蓝牙响应命令、LCD 能正常亮、串口也能打印，**但以下 5 组物理输出会全部“失灵”而退回纯硬件模拟模式**：
  1. `PE9/11/13/14 (AIN1/2, BIN1/2)` → 经 `U4` 控制 `DRV8833`
  2. `PD2 (MCU_MOTOR_EN)` → 经 `U18.6->7` + `U3.5->6 (MOTOR_nENABLE)` 关断/使能 `U4.15` 与积分清零芯片 `U8`
  3. `PD8 (MCU_PARK_LAMP)` → 经 `U18.10->9` + `R110 (1k)` 驱动 `Q4 (BSS138BK)` 点亮双红停车灯
  4. `PC9 (MCU_BUZZER)` → 经 `U18.13->12` + `R109 (1k)` 驱动 `Q3 (BSS138BK)` 鸣响 5V 有源蜂鸣器
  5. `PB9 (MCU_US_TRIG)` → 经 `U18.3->4` 输出超声触发脉冲至 `J_US.2`

#### B 组：不经过 `MODE_MCU` 的直接控制通道
1. **激光发射 (`PC8 MCU_LASER_EN`)**：`PC8` → `R111 (1 kΩ)`（配 `R125 = 47 kΩ` 强下拉）→ `Q5 (BSS138BK)` 栅极 → 低侧拉通 `J_LSR.2`（`J_LSR.1` 通过 `R123 = 0 Ω` 接 `SYS_5V`）。
2. **云台舵机 (`PC7` + `PA15`)**：**双信号硬件与门** `U20 (74AHCT1G08)`，**必须同时满足 `PC7 = HIGH` 且 `PA15 (TIM2_CH1)` 有 PWM 脉宽**，才能从 `U20.4 -> R120 (100 Ω)` 输出到 `J_SRV.1`。注意即使未插电池只用 `USB` 供核心板 3.3V，只要主板没 `SYS_5V/SERVO_5V`，`U20` 和舵机都不会动！
3. **核心板蓝灯 (`PC0`)**：`3.3V -> R3 (1.5kΩ) -> LED1 -> PC0`（低电平 `0V` 点亮）。

#### 三步快速输出排查清单（配合蓝牙 `outtest` / `bench` 命令）

在确保**电池已供电 (`SYS_5V ≈ 5V`、`SERVO_5V ≈ 5V`)**、小车处于停止状态时，逐项下发命令配合万用表排查：

| 检查目标 | 发送蓝牙测试命令 | 第一级检测点（核心板输出 / 门控） | 第二级检测点（驱动输入 / 负载） | 常见故障原因 |
| :--- | :--- | :--- | :--- | :--- |
| **总门控前提** | 无需发命令（上电即生效） | 测 **`J_C2-6 (MCU_PRESENT_n)`** 应为 **`0.0 V`**；测 **`U3.2 / U4.1 / U18.1 (MODE_MCU)`** 应为 **`5.0 V`** | 若 `U3.2 = 0 V`：先看 `J_C2-6` 对 `GND` 通断 | `J_C2-6` 虚焊或核心板偏插，导致全车退回模拟模式 |
